Run `product-engineering` via `product-strategist`:

1. Problem statement: who fails at what, with evidence (or name the missing instrumentation).
2. Outcome: one primary metric with baseline, target, and measurement window.
3. Working-backwards paragraph: the announcement in user words; if it reads boring, fix the scope.
4. Appetite and scope hammering: smallest valuable slice, no-gos, rabbit holes.
5. Ordering by cost of delay vs job size; build-vs-buy with exit cost when a commodity capability
   is involved.
6. Verdict: do / defer / don't, plus the trigger that would change the answer.

Sequencing after acceptance routes to `deep-planner`; delivery etiquette stays per `AGENTS.md` §3.
