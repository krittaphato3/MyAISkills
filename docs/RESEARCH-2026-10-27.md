## Addendum — no-native web tools (same day)

Requirement: searching and page reading must work on models/harnesses with **no native web
search, WebFetch, or browser** — bash only.

Built `tools/webfetch.mjs` (Node 18+ stdlib): redirect following, gzip/brotli/charset decoding,
HTML → compact markdown (headings, lists, code, links), `--max-chars`, `--focus`, `--raw`,
`--json`. `tools/web_search.mjs`'s `--fetch` path now delegates to it (its old extractor
collapsed all whitespace and ignored redirects; search itself was unchanged).

Wired: `web-search` rewritten around the path ladder (native tools → local CLIs → Playwright
MCP), `browser-automation` skill + agent gained the CLI fallback, `deep-researcher` uses the
CLIs when native tools are missing, `/search` updated to repo-relative paths, `/fetch` added,
AGENTS.md §7/§7.1 routes the fallback.

Live verification: search returns real results; fetch handles redirects (http→https), JSON APIs,
`--raw`, `--focus`, and 404s (`ok:false`, status, error in output).

Design notes: no external research was needed for this implementation; the engine split
(CLI = DuckDuckGo HTML with no browser, Google stays the browser default) follows the existing
`browser-automation` doctrine, and the extractor uses standard readability heuristics
(strip script/style/nav/footer, preserve structure).
