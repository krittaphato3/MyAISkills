# Research note: what changed on 2026-10-30, and why

Scope: current pstack, public skill repositories, and published engineering practice on shipping
code with agents. The goal was to reduce shipped bugs and repeated corrections without raising
token spend for a single developer.

## Adopted

1. **Single router.** `poteto-mode` and `ozone-mode` both claimed the entry point. Two routers
   with overlapping triggers produce contradictory instructions. Ozone is now the only router;
   poteto forwards.
2. **Playbook routing with visible skips.** Steps copied into the todo list verbatim, skips
   recorded with a reason. This is pstack's core anti-drift mechanism.
3. **Evidence labels.** Every claim marked measured, inferred, or guess. "Never hand the human a
   check you could run" became a non-negotiable.
4. **Green is not safe.** Independent verdict on the exact head, invalidated by any later edit.
   This is the gap that let bugs reach the user after a green suite.
5. **Attack the premise.** Added as a principle: a second failed fix means one wrong assumption,
   not two bugs.
6. **Explain the number.** Added as a principle: no benchmark, latency, or cost figure is reported
   without its limiter and an alternative-explanation check.
7. **Ship gate.** A single command that audits claims against the diff, re-runs checks after the
   final edit, and states blast radius and unverified items.
8. **Mutation testing over mandated TDD.** The research finding is that mandating TDD inside the
   agent loop shows no measurable quality gain, while mutation testing measures whether tests can
   fail. TDD stays mandatory for bug fixes, where red-first has real signal.
9. **Two-axis review.** Standards and spec reviewed separately, because a clean diff that solves
   the wrong problem passes a blended review.
10. **Web app QA as a skill.** Drive the real browser, check console and network, exercise empty,
    loading, and error states, verify side effects, clean up.
11. **Slim `AGENTS.md`.** From 32KB to about 10KB, loaded on every request. Roster tables and the
    full skill catalog moved to generated docs. This is the largest single token saving.
12. **Subagent contract.** Six-field brief, five-subagent wave cap, reviewers never edit, the
    author never certifies, mandatory no-fanout line to stop recursion.
13. **Four more pstack workflow skills, adapted.** `benchmark-checklist`, `sharpen`, `ketchup`, and
    `in-your-own-words`. They are wired into the ozone router rather than shipped as a second
    workflow, and the Graphite, bot-UI, and external model references were dropped because this
    harness cannot execute them.

## Rejected, with reasons

- **Formal verification (TLA+) and statechart skills.** High value for concurrency work, high cost
  in tokens and setup for a solo developer's day-to-day. Available as an optional add later.
- **Installing a second methodology spine.** Superpowers and pstack both want to own the plan and
  the review step. Running both doubles the context tax and creates conflicting instructions.
- **Bulk agent marketplaces.** 200-agent catalogs are a routing problem, not a capability gain.
- **Unbounded parallel fan-out.** Anthropic's own guidance is that coding parallelizes worse than
  research, and multi-agent runs cost roughly 15x a single thread.

## Honest limits

- The TDD finding rests on one small greenfield experiment. It is a signal against mandating TDD,
  not a refutation of TDD.
- Behaviour verification remains unsolved: browser and E2E gates catch what someone thought to
  check. This config requires stating what was not verified rather than implying coverage.
- Correctness is outside any sensor's remit. If the requirement was never stated, no gate catches
  it; `requirements-elicitation` is the mitigation.
